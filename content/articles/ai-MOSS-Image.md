## 1. 概述

MOSS-Image 是由 MOSI.AI、SII、复旦大学和上海交通大学联合开发的开放文生图系统，旨在缩小开源模型与闭源图像生成系统（如 GPT Image 2、Seedream 5.0 Pro、Qwen Image 3.0 Pro 等）之间的差距，特别是在**密集文本渲染**和**复杂布局生成**这两个开源模型长期薄弱的领域取得突破。

系统的核心由两部分组成：

- **5B 参数单流扩散 Transformer（DiT）**：从零开始预训练的基础生成模型，支持双语（中英文）长文本渲染和精确布局控制。
- **意图感知的智能体提示增强模块（Agentic Prompt Enhancement, PE）**：将简短的用户请求转化为详细的内容和布局规范，连接用户意图与生成器。

### 核心性能亮点

| 评测基准 | MOSS-Image 成绩 | 对比 |
|----------|----------------|------|
| LLTB (Mean-6) | **96.3** | Qwen Image 2512 仅 64.9，领先 31.4 个百分点 |
| 7Bench (mIoU_det) | **0.88** | Ideogram 4 仅 0.44，大幅领先 |
| 7Bench (Layout AUC) | **0.70** | Ideogram 4 仅 0.20 |
| RLA 端到端系统 | **1698.70 Elo** | 排名第二，仅次于 GPT Image 2 (1844.35) |
| RLA 共享增强提示 | **1807.34 Elo** | 主干模型排名第一 |

### 2.1 数据来源与构成

### 2.2 核心数据策略：标注而非过滤

MOSS-Image 在数据策略上有一个重要的反直觉设计——**"Annotate rather than filter"（标注而非过滤）**。

在去重和 AI 图像移除之后，**不再施加额外的人工质量过滤**。这是一个经过实验验证的预训练选择。团队在 1B 消融实验中发现：

- **额外过滤反而损害生成质量**：在 1.6M 步训练后，过滤后的模型在 GenEval、OneIG 和 FDR6-LAION 上表现更差，特别是文本渲染能力大幅下降——OneIG 文本分数从 0.5243 骤降至 0.1180。
- **残余属性（水印、模糊人脸、压缩伪影）被纳入文本标注**，而不是作为排除标准。

> **设计理念**：保留真实世界数据分布的广度，通过标注而非过滤来处理"低质量"属性。

### 2.3 多粒度结构感知标注

每张图像通过 Gemma 4 [19] 生成三种语义粒度的描述：

| 描述类型 | 平均 Token 长度 | P10 | 中位数 | P90 |
|----------|---------------|-----|--------|-----|
| 短描述（单句摘要） | 20.86 | 16 | 20 | 26 |
| 中描述（段落级） | 76.61 | 59 | 75 | 97 |
| 长描述（详细描述） | 235.12 | 153 | 193 | 293 |

关键设计要点：

1. **保留换行结构**：标注中的可见文本逐字转录，保留换行符（`\n`），因为换行本身也是一种布局信息，为多行文本渲染提供显式监督。
2. **结构化布局标注**：对部分图像子集构建包含全局描述和局部元素（边界框、类别、文本转录、排版属性）的 JSON 结构标注。
3. **Caption 采样策略**：原始 caption 与重新生成的 caption 以 20:80 的比例采样；三个粒度之间均匀采样（1:1:1）。

### 2.4 训练数据特点小结

- 训练 caption 以**英文为主**，无专门的中文标注。
- 尽管如此，模型仍展现出强大的**中文长文本渲染能力**（LLTB 中文分数最高达 92.4）。
- 数据涵盖通用图像、医学图像、遥感图像、艺术作品、地标建筑、海报等多种领域。

## 3. 模型创新点

### 3.1 架构设计

#### 3.1.1 5B 单流扩散 Transformer

MOSS-Image 采用**单流（single-stream）DiT 架构**，文本和图像 token 在同一 Transformer 中联合处理，而非双流（dual-stream）设计。

| 组件 | 配置 |
|------|------|
| 扩散生成器 | 5B 单流 Transformer |
| 文本编码器 | Qwen3.5-9B（冻结） |
| 文本适配器 | 线性投影 4096→3072 + 两个文本专用 Transformer 块 |
| 主干深度 | 42 层（不含文本适配器和编码器） |
| 隐藏维度 | 3072 |
| 注意力头 | 24 头 × 128 维 |
| FFN 隐藏维度 | 8192 |
| VAE | FLUX.2 VAE（冻结），32 通道，下采样因子 8 |
| 隐空间 Patch 大小 | 2×2，每个 token 128 个值 |
| 有效图像步长 | 16 像素 |

#### 3.1.2 SiTU-GLU 前馈层

MOSS-Image 引入了来自 Kimi K3 [14] 的 **SiTU-GLU 前馈层**，结合了 SiLU 门控和平滑截断函数：

$$\text{FFN}(\mathbf{x}) = W_o \left[ c_{\beta_g}(\mathbf{g}) \odot \text{sigmoid}(\mathbf{g}) \odot c_{\beta_u}(\mathbf{u}) \right]$$

其中 $c_\beta(v) = \beta \tanh(v/\beta)$ 为平滑截断函数，$\beta_g, \beta_u > 0$ 控制饱和度。这一设计有助于数值稳定性和训练收敛。

#### 3.1.3 4D RoPE 位置编码

MOSS-Image 设计了四维旋转位置编码（4D RoPE），将每个注意力头的特征分为四个子空间：

$$\mathbf{z} = [\mathbf{z}_r; \mathbf{z}_t; \mathbf{z}_w; \mathbf{z}_h]$$

对应四个坐标轴 $(r, t, w, h)$：
- **r**: 参考索引轴（reference index），为未来扩展到参考图像条件生成预留
- **t**: 序列位置轴（temporal/sequence position）
- **w, h**: 空间宽度和高度轴

在当前无参考输入的设定下，所有 token 使用 $r=0$，使得参考子空间保持不旋转，产生**部分 RoPE（partial RoPE）**。具体配置为：每个头的 128 维中，前 32 维不旋转，剩余 96 维使用 $(t, w, h)$ 编码。

> **设计考量**：消融实验表明，不同坐标分配方案在整体生成质量上差异不大，但各指标间存在权衡。保留独立的参考索引轴为未来扩展到图像编辑和参考条件生成提供了可能，而无需改变位置编码结构。

### 3.2 渐进式训练策略

训练分为三个阶段，逐步增加图像分辨率和文本上下文容量：

| 阶段 | 分辨率 | 文本 Token 限制 | 特点 |
|------|--------|-----------------|------|
| Stage 1 | 较低分辨率 | 较短文本 | 基础训练 |
| Stage 2 | 中等分辨率 | 中等文本 | 过渡到逐 token 归一化 |
| Stage 3 | 保持宽高比，≤1024² 像素 | 4096 tokens | 最终阶段，步 310,000 |

Stage 3 最终配置：
- 图像尺寸对齐到 16 的倍数
- 目标图像面积上限 1024² 像素
- 单设备处理 8576 个图文 token
- 512 设备 × 2 梯度累积步 = 名义容量 8,781,824 tokens/更新
- 使用 EMA（指数移动平均）权重

### 3.3 Hybrid Muon–AdamW 优化器

MOSS-Image 在整个预训练过程中使用 **Muon-AdamW 混合优化器**：
- **Muon**：用于可更新的二维矩阵参数
- **AdamW**：用于非矩阵、嵌入类、输出头等参数

在 1B 消融实验中验证了其收敛优势：

| 目标损失 | AdamW 所需步数 | Muon-AdamW 所需步数 | 步数节省 |
|----------|---------------|---------------------|----------|
| 0.41 | 385K | 257K | 33.2% |
| 0.403 | 1317K | 939K | 28.6% |

优化器超参数：

| 参数 | 值 |
|------|-----|
| 学习率（AdamW） | 5×10⁻⁵ |
| 学习率（Muon） | 5×10⁻⁵（RMS 匹配） |
| AdamW β₁, β₂ | 0.9, 0.95 |
| Muon 动量 | 0.95，5 步 Newton-Schulz |
| 权重衰减 | 0.01 |
| 梯度裁剪 | 1.0 |
| EMA | 0.9999 |
| 学习率预热 | 2000 步 |

### 3.4 流匹配损失与噪声采样

采用 **Flow-matching** 损失函数（公式 3），文本 token 不参与预测损失，不同分辨率的图像按有效 token 数量比例贡献损失。

Stage 3 采用四段式噪声采样调度（表 2），核心特点：
- 最终阶段使用截断 logit-normal 采样（$\mu=-1.09$, $s=0.95$），截断点 $a=0.95$
- 混入 1% 均匀采样
- 前两阶段额外以 0.01 概率采样全噪声端点
- 逐步从 shift=3 过渡到 shift=1

### 3.5 意图感知的智能体提示增强（PE）

这是 MOSS-Image 区别于其他文生图系统的核心系统创新。PE 模块基于 GPT-6 实现，包含三个关键能力：

1. **意图特定的任务路由**：根据请求的媒介类型（海报、信息图、UI 界面）选择不同的任务模块，每个模块有专门的内容和设计指导。
2. **知识与视觉上下文检索**：Agent 通过网络和图像搜索获取参考资料，检查视觉参考以开发内容和构图。
3. **可执行布局规划**：输出 JSON 格式的结构化规范，包含文本、元素、边界框、排版和空间关系，通过生成器共享的文本条件接口直接传递。

PE 模块输出的 JSON 包含 8 个根字段：`scene_type`、`gen_brief`、`aspect_ratio`、`layout`、`elements`、`anchors`、`must_not`、`palette`。与训练时的标注格式相比，推理时额外增加了 `aspect_ratio` 和 `must_not` 字段。

### 3.6 双重评测基准

MOSS-Image 团队提出了两个新评测基准：

#### LongLongTextBench (LLTB)

| 特性 | LongTextBench | LLTB |
|------|--------------|------|
| 任务数 | 320 | 240 |
| 总字符数 | 38,489 | 321,545 |
| 平均字符数 | 120.3 | 1,339.8 |
| 最长目标 | 482 | 2,863 |

LLTB 包含 120 英文 + 120 中文任务，每个语言有三个长度区间（短/中/长）。英文源自 Project Gutenberg 文学作品，中文古典文本包含《孟子》《中庸》《大学》，现代文本包含鲁迅作品（含《阿Q正传》12 篇）。

#### RealLayoutArena (RLA)

61 个任务从手工筛选的设计参考构建（20 海报 + 20 信息图 + 21 UI 界面），使用盲测成对人类比较，评估指令遵循、渲染质量和空间组织。

## 4. 改进与思考

### 4.1 核心问题诊断

MOSS-Image 团队将当前开源 T2I 模型的差距归结为两个耦合挑战：

1. **渲染挑战（Rendering）**：准确再现长文本并遵循空间约束。
2. **规范挑战（Specification）**：将简洁的用户请求转化为内容和布局指令，细节程度与请求相匹配。

> **关键洞察**：单独任何一个能力都不够——详细的规范不保证忠实渲染，渲染能力本身也不能解决用户未明确的内容和设计决策。这需要一个连接意图感知规范与忠实渲染的系统。

### 4.2 关键设计思考

#### 4.2.1 统一文本条件路径

MOSS-Image 的一个核心设计决策是：**自然语言描述和结构化布局规范共享同一文本条件路径**。这意味着模型可以通过自然语言或 JSON 布局任一形式接收指令，无需独立的布局控制模块。

这一设计的优势在于：
- 简化了模型架构，避免了多条件模块的复杂性
- 允许通过提示增强模块灵活切换两种条件形式
- 自然语言和结构化布局可以混合使用

#### 4.2.2 换行即布局

团队提出了一个深刻洞察：**"Text line breaks are also a form of layout"（文本换行也是一种布局）**。

消融研究发现，提示中带有显式换行符时：
- 在去噪过程早期（第 8 步），多行文本的字符内容就已经可以辨认
- 不带换行符时，中间步骤多行文本保持模糊，最终步骤仍有畸形字符
- 这表明换行边界有助于模型更早地建立每行内容，改善最终文本渲染

#### 4.2.3 坐标表示的泛化性

研究发现**零中心绝对边界框坐标**在训练中未见过的分辨率上泛化效果优于归一化到 [0, 1000] 的相对坐标。这一发现直接影响了推理时的坐标约定。

#### 4.2.4 LongTextBench 已饱和

团队发现 LongTextBench 已接近饱和——强模型得分集中在 96.05–98.85 之间，且其目标文本平均仅 120.3 个字符，无法有效区分长文本渲染能力。这促使他们构建了 LLTB，平均字符数达到 1,339.8（约为前者的 11.1 倍）。

### 4.3 局限性与未来方向

MOSS-Image 团队坦诚地指出了当前模型的局限：

1. **不支持参考图像条件**：当前主干仅支持文生图，不能直接以参考图像为条件或进行图像编辑。
2. **提示增强依赖外部 LLM**：PE 模块依赖 GPT-6，其在美学判断、参考解释和事实错误方面的局限会影响规范质量。
3. **计算预算限制**：图像条件生成和迭代设计精化在未来工作计划中，受限于当前计算预算。

## 5. 微调及蒸馏训练

### 5.1 SFT 后训练

MOSS-Image 提供两个版本：

| 版本 | 描述 |
|------|------|
| **MOSS-Image-Base** | 基础文本到图像生成模型（预训练 checkpoint） |
| **MOSS-Image-SFT** | 在精选数据上从基础版本微调而来，具有更清晰的文本分组和更有组织的布局 |

SFT 版本针对布局组织和文本分组进行了优化，更适合实际应用场景。

### 5.2 社区微调框架：KohakuMossTrainer

MOSS-Image 官方推荐 `KohakuMossTrainer` 进行微调训练，提供全量微调和 LyCORIS（含 LoRA）训练：

| 特性 | 支持 |
|------|------|
| 优化器 | 广泛的优化器支持 |
| 混合精度 | BF16 / FP16 / FP8 / MXFP8 / INT8 |
| 多 GPU | DDP / FSDP / 流水线并行 |
| 最低 VRAM | 6GB（适配器训练） |
| 平台 | Windows、Linux |
| GPU 支持 | NVIDIA (SM70–SM120)、Intel Arc |

### 5.3 社区微调项目

1. **DiffSynth-Studio**：支持 MOSS-Image 的全量微调和 LoRA 训练
2. **MOSS-Image-SFT-DeBand**：由社区开发的 LoRA，用于减少垂直色彩条带问题
3. **MOSS-Image-FP16-fixed**：FP16 兼容的变换器权重，降低部署门槛

### 5.4 蒸馏训练

社区已开始蒸馏探索：

1. **MOSS-Image-SFT-8-steps-dmd**：由 lodestones 开发的 **8 步 DMD（Distribution Matching Distillation）蒸馏版本**，将默认 50 步采样大幅压缩到 8 步，显著提升推理速度。

### 5.5 推理优化

MOSS-Image 的推理支持多种优化配置：

**采样设置（默认）**：
- 采样器：Flow-matching Euler
- 步数：50
- CFG：3
- Shift：5
- 层跳过：第 22 层负分支跳过

**内存模式**：
- GPU 驻留模式：整个模型保留在 GPU 上
- 组件模式：在 CPU 和 GPU 之间移动模型组件
- 顺序模式：低内存使用，推理较慢

**推理引擎支持**：SGLang、vLLM-Omni、ComfyUI

## 6. 与 Qwen-Image-2.1 对比

### 6.1 背景

Qwen-Image-2.1 [39] 是阿里巴巴 Qwen 团队发布的"紧凑、高效、统一的图像创作"模型。MOSS-Image 技术报告在致谢中感谢了 Qwen 团队，且使用了冻结的 Qwen3.5-9B 作为文本编码器，两者在技术路线和定位上有显著差异。

### 6.2 架构对比

| 维度 | MOSS-Image | Qwen-Image-2.1 |
|------|------------|-----------------|
| **主干架构** | 单流 DiT (Single-stream) | 双流 DiT (Dual-stream)（注：Qwen-Image 系列传统设计） |
| **参数规模** | 5B（扩散生成器） | 紧凑高效设计 |
| **文本编码器** | Qwen3.5-9B（冻结） | 自研 Qwen LLM |
| **VAE** | FLUX.2 VAE（冻结，32 通道） | 自研 VAE |
| **FFN 设计** | SiTU-GLU（带平滑截断） | 标准 GLU |
| **位置编码** | 4D RoPE (r,t,w,h) | 3D RoPE (t,w,h) |
| **优化器** | Hybrid Muon-AdamW | AdamW 系列 |
| **条件接口** | 统一文本路径（自然语言+JSON 布局） | 文本+独立布局控制 |
| **提示增强** | 内置 Agentic PE (GPT-6) | Qwen-Image-Agent [12]（独立模块） |

### 6.3 设计理念对比

| 维度 | MOSS-Image | Qwen-Image-2.1 |
|------|------------|-----------------|
| **核心目标** | 密集文本+复杂布局 | 紧凑高效的通用生成 |
| **数据策略** | 标注而非过滤（广覆盖） | 质量过滤（精选数据） |
| **布局控制** | 通过文本接口统一（JSON→文本编码器） | 独立布局条件模块 |
| **Agent 设计** | 结构化 JSON 输出，直接驱动生成 | 自然语言增强，不直接布局 |
| **参考索引** | 预留 r 轴支持未来图像编辑 | 当前不支持 |

- DiffSynth-Studio：另一种微调和 LoRA 训练方案

### 7.4 评测基准贡献

MOSS-Image 团队贡献了两个重要评测基准：

1. **LLTB（LongLongTextBench）**：填补了长文本渲染评测的空白，平均字符数是 LongTextBench 的 11 倍。
2. **RLA（RealLayoutArena）**：首个端到端复杂图形生成的人评竞技场，使用 Bradley-Terry 评分。

这些基准为整个文生图社区提供了更全面、更有区分度的评估工具。

## 8. 总结

MOSS-Image 是一个在密集文本渲染和复杂布局生成领域取得重大突破的开源文生图系统。其核心贡献可归纳为：

### 技术层面

1. **5B 单流 DiT 从零预训练**：证明单流架构在文本渲染和布局控制上的竞争力
2. **统一文本条件接口**：自然语言和结构化布局共享同一条件路径，简化架构同时增强灵活性
3. **"标注而非过滤"的数据策略**：经实验验证，广覆盖数据优于质量过滤
4. **Hybrid Muon-AdamW 优化器**：在训练收敛效率上实现 28-33% 的步数节省
5. **4D RoPE 设计**：预留参考索引轴，为未来图像编辑扩展奠定基础
6. **Agentic PE 模块**：将简短用户请求转化为详细结构化布局规范

### 评测层面

1. LLTB 上开源 SOTA（96.3 Mean-6），领先 Qwen Image 2512 达 31.4 个百分点
2. RLA 端到端排名第二（仅次于 GPT Image 2），主干在共享提示下排名第一
3. 7Bench 布局控制大幅领先（mIoU_det 0.88 vs 次优 0.44）

### 社区层面

1. 完整开源模型、训练方案和评测框架
2. 多框架部署支持（ComfyUI、SGLang、vLLM-Omni、Diffusers）
3. 活跃的社区微调和蒸馏生态
4. 贡献两个高质量评测基准

MOSS-Image 证明了开源模型在密集文本和复杂布局生成领域可以接近甚至超越部分闭源系统，为文生图社区的发展提供了重要的技术基础和评测工具。
